# 프로젝트 정리

`CLAUDE.md`와 현재 기능을 읽고 프로젝트 범위 안에서 수행한다.

| 동작 | 별칭 | 수행 내용 |
| --- | --- | --- |
| 점검 | `check`, 인수 없음 | 발견사항만 보고 |
| 정리 | `run`, `fix` | 요청한 범위의 확인된 문제 수정 |

## 점검 항목

- 완료 이력이 오래된 것부터 최신 순서이며 중복 기록이 없는가?
- 디버깅 로그, 쓰지 않는 import, 오래된 TODO와 `@ts-ignore`가 남았는가?
- 사용하지 않는 파일처럼 보여도 동적 import, 라우팅 규칙, 설정, 문서에서 참조하고 있지는 않은가?
- 프로젝트 개요·현재 기능·스펙이 실제 구현 상태와 맞는가?
- 앱에서 사용하는 환경 변수 이름과 `apps/web/.env.example`, 배포 문서가 일치하는가? 루트 `.env.example`은 Docker 이름·포트용이며 앱 변수와 구분한다. 실제 값은 출력하지 않는다.
- 스킬의 상대 링크와 프로젝트 문서 경로가 유효한가?

## 처리

발견사항은 번호, 파일 위치, 근거, 제안으로 보고한다. 점검 모드에서는 파일을 수정하지 않는다. 정리를 요청받았다면 이미 허용한 범위의 분명한 문제를 수정하고 결과를 보고한다. 사용자가 항목을 지정하면 그 항목만 수정한다.

용도가 불분명한 파일 삭제나 서비스 동작 변경은 단순 정리에 포함하지 않는다. 아직 만들지 않은 기능이나 빈 템플릿을 오류로 보고하지 않는다. 기존 사용자 변경을 되돌리지 않는다.

변경 영향에 맞는 린트·검증을 실행하고 무엇을 바꿨는지 기록한다. 이 스킬만으로 커밋·푸시하지 않는다.
