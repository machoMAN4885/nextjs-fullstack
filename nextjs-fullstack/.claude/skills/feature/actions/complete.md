# 완료 기록

1. 스펙의 수용 기준과 최신 검증 결과를 확인한다. 필요한 검증이 실패하거나 미실행이면 완료로 표시하지 않고 남은 작업을 기록한다.
2. 통과한 경우 현재 상태를 `완료`로 바꾸고 연결된 스펙에도 결과를 남긴다.
3. 완료 이력 맨 아래에 날짜, 기능명, 스펙 경로, 변경 요약, 실제 검증 근거를 추가한다. 같은 완료를 반복 요청하면 중복 기록을 추가하지 않는다.
4. 기능 후보 목록의 상태를 맞춘다. 다음 기능을 불러오기 전까지 현재 작업의 결과를 보존한다.
5. 커밋·푸시를 사용자가 요청했다면 `main`과 작업 트리를 확인하고 이 기능의 파일만 반영한다. 별도 요청이 없으면 문서 정리에서 끝낸다. 자동 병합·브랜치 삭제·Vercel 배포는 하지 않는다.

최종 답변에는 완료한 결과, 검증, 남은 제한을 간결하게 적는다. 검증되지 않은 운영 배포나 DB 연결을 완료로 보고하지 않는다.
