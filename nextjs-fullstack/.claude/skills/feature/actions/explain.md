# 구현 설명

현재 기능, 스펙, 작업 시작 기준점과 실제 변경 파일을 읽는다. 파일을 수정하지 않는다.

1. 사용자가 어떤 결과를 얻는지 먼저 설명한다.
2. 주요 파일별 역할과 바뀐 이유를 설명한다.
3. 해당 기능의 요청 흐름을 화면 → Server Component/Action/Route Handler → Prisma → PostgreSQL 순서로 설명한다. 실제로 존재하는 부분만 다룬다.
4. 입력·권한 검증과 오류 처리가 어디서 이루어지는지 연결한다.
5. 확인한 동작과 아직 확인하지 못한 부분을 구분한다.

코드를 줄마다 읽어주기보다 사람이 판단해야 할 결정과 데이터 흐름을 한국어로 설명한다. 아직 구현되지 않았다면 스펙상의 계획이라고 명시한다.
