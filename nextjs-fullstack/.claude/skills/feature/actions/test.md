# 검증

현재 기능의 수용 기준과 변경 파일을 읽고 검증을 연결한다.

- 서버 액션, 입력·권한 검증, 유틸리티, 경계 조건에 의미 있는 로직이 있으면 Vitest 테스트를 작성하거나 수정한다. 성공뿐 아니라 오류·권한 없는 요청도 확인한다.
- 단순 CSS나 정적 화면에 구현을 그대로 반복하는 테스트를 만들지 않는다. 관련 기존 테스트가 있으면 실행한다.
- 테스트가 있으면 `npm run test`를 실행한다. 없으면 `테스트 없음`을 기록한다. 빈 테스트를 통과시키려고 설정을 바꾸지 않는다.
- 앱이 있으면 `npm run lint`, `npm run typecheck`, `npm run build`를 실행한다. 아직 소스가 없는 템플릿에는 앱 빌드 통과를 주장하지 않는다.
- DB 변경이 있으면 로컬 마이그레이션·Client 생성·상태와 실제 연결을 확인한다. 운영 DB로 테스트하지 않는다.
- UI 변경이 있으면 브라우저에서 수용 기준의 흐름과 필요한 화면 크기를 확인한다. 사용할 수 없는 도구는 제한으로 기록한다.

명령은 프로젝트 루트에서 Docker의 `docker compose exec tools`를 앞에 붙여 실행한다. `tools`의 작업 위치는 `/workspace/apps/web`이다. 호스트 npm은 `apps/web/`에서만 실행한다. `context/current-feature.md`에 명령, 결과, 수용 기준, 미실행 이유를 남긴다. 실패를 고치면 영향을 받는 검증을 다시 실행한다.
