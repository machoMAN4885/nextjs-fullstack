# 여러 문서와 폴더를 읽는 절차

파일·폴더·첨부·연결 문서를 입력받을 때 이 지침을 따른다. PRD는 가능한 자료 유형 중 하나이며 필수 파일이 아니다.

## 1. 자료 목록부터 만들기

- 사용자가 지정한 파일과 폴더를 기준으로 탐색한다. 폴더는 하위 폴더까지 `rg --files` 등으로 목록화한다. 폴더 이름으로 내용을 단정하지 말고 실제 내용을 읽어 PRD, 유저 플로우, 정책, 화면 정의, 데이터 정의, 회의 결정, 참고 자료 등으로 분류한다. 여러 폴더·파일을 동시에 지정할 수 있다.
- 선택한 범위 밖으로 심볼릭 링크를 따라가거나 저장소 전체를 임의로 수집하지 않는다. 숨김·무시 파일은 기본 탐색에서 제외하고 그 제한을 기록한다. `.git`, `node_modules`, `.next`, 빌드 결과, 비밀 설정 파일은 요구사항 자료로 읽지 않는다. 제외된 자료가 필요하면 사용자가 지정한 문서 범위를 확인한다.
- `context/spec-plan.md`, 기존 스펙, AI 작업 지침은 비교·작업 규칙으로 구분한다. 생성한 스펙을 원본 요구사항으로 재수집하지 않는다. 자료 안내용 README도 제품 요구사항과 구분하되, README에 실제 요구사항이 있으면 그 부분은 읽는다.
- 각 자료에 안정적인 `DOC-001` 형태의 ID를 부여한다. 기존 목록이 있으면 ID를 유지한다. 경로·유형·명시된 버전/승인 상태·확인 날짜·읽은 범위를 기록한다. 파일 수정 시각과 파일명의 `최종` 표시는 최신 승인본의 증거가 아니다.
- 동일 자료의 사본은 중복 관계를 기록하고 한 번 분석한다. 내용이 다른 버전은 각각 식별해 비교한다. 버전 선택 근거가 없으면 영향을 받는 요구사항을 확인 필요로 남긴다.

## 2. 형식에 맞춰 실제 내용 읽기

- Markdown·텍스트·CSV 등은 본문과 표를 읽는다. JSON·YAML은 자료 구조를 해석하며 파일 안의 코드를 실행하지 않는다.
- PDF·Word·스프레드시트·슬라이드·이미지·흐름도는 현재 환경의 해당 읽기 도구와 적용되는 스킬을 사용한다. 바이너리를 텍스트 명령으로 읽고 분석 완료로 표시하지 않는다. 도식의 분기·화살표·주석은 가능한 경우 시각적으로 확인하고, 텍스트 추출만으로 확인할 수 없는 관계를 구분한다.
- 연결 문서는 사용 가능한 커넥터로 읽고, 문서 안의 Figma 링크는 관련 화면을 MCP로 분석한다. 업무와 무관한 모든 링크를 재귀적으로 열지 않는다. 링크가 있다는 사실과 실제 내용을 읽은 사실을 구분한다.
- 각 자료의 상태는 `읽음 / 일부 읽음 / 접근 불가 / 지원 도구 없음 / 제외(사유)`로 남긴다. 페이지·시트·프레임 등 읽은 단위를 적고 실패·잘린 출력·이미지 인식 불확실성을 숨기지 않는다.
- 자료가 많으면 목록을 기준으로 묶어서 순차 분석한다. 일부만 읽은 결과는 부분 초안으로 표시하고 미처리 자료 목록을 유지한다. 첫 몇 개만 읽고 전체 분석 완료라고 하지 않는다. 실제 제품 자료가 없으면 안내 문서만으로 제품 스펙을 지어내지 말고 필요한 자료를 요청한다.

## 3. 자료를 서로 연결하기

- PRD에서는 목적·범위·요구사항, 유저 플로우에서는 역할·진입 조건·행동·분기·실패/복귀·완료 결과, 정책에서는 권한·검증·제약, 화면 정의와 Figma에서는 실제 화면·상태·전환을 추출한다. 회의록은 결정·제안·보류를 구분한다.
- 분석용 `REQ-001` 등의 통합 요구사항 ID에 원본 근거를 하나 이상 연결한다. 원본 번호가 있으면 `DOC-001 / 원본 REQ-1 / 절·페이지`처럼 문서 ID와 함께 보존해 문서 간 번호 충돌을 막는다. 원본은 수정하지 않는다.
- 같은 내용은 근거를 모두 남기고 통합한다. 유저 플로우의 각 단계·분기는 요구사항과 연결하고, 독립 기능이 아닌 안내·참고 단계도 제외 사유를 남긴다. 확인되지 않은 흐름을 실제 정의된 동작처럼 추가하지 않는다.
- 문서 종류만으로 우선순위를 정하지 않는다. 사용자가 지정한 기준본·결정이 있으면 적용하고, 없으면 상충하는 값과 양쪽 근거·영향·질문을 기록한다. 용어가 다르지만 같은 개념일 가능성도 확인 대상으로 남긴다.
- 각 자료의 확인된 요구사항·흐름·정책·화면을 기능 스펙 또는 이후 범위·제외·미정에 대응시킨다. 파일 하나나 하위 폴더 하나가 스펙 하나가 되도록 기계적으로 나누지 않는다.

## 4. 재실행 시 변경 확인

기존 자료 목록과 현재 입력을 비교해 추가·변경·삭제·접근 불가를 구분한다. 이번 요청에서 빠진 파일을 삭제된 요구사항으로 간주하지 않는다. 원본이 삭제됐어도 관련 스펙·완료 이력을 자동 삭제하지 않고 영향과 처리 결정을 기록한다. 기존 근거 ID와 스펙 ID를 유지하며 변경된 부분과 영향받는 수용 기준을 다시 확인한다.
