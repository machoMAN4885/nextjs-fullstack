# 프로젝트 조사

`CLAUDE.md`와 프로젝트 개요를 읽는다. 인수가 파일이면 `context/research/`에서 찾고, 자연어면 목적·질문·결과 경로를 정리한다. 결과 경로를 지정하지 않았다면 `docs/<주제>.md`를 사용한다. 같은 경로에 기존 문서가 있으면 먼저 읽고 필요한 부분을 갱신한다.

## 절차

1. 질문과 관련된 스펙·소스·설정을 읽는다. 소스가 없으면 계획 단계임을 명시한다.
2. 버전별 동작이나 바뀔 수 있는 정보는 해당 기술의 공식 문서에서 확인한다. Next.js 16 / Prisma 7 / Node.js 24라는 프로젝트 조건을 유지한다.
3. DB 조회가 필요하면 대상 환경을 확인하고 허용된 개발 DB에서 필요한 읽기만 한다. 기본 환경은 로컬 Docker PostgreSQL이다.
4. 확인한 사실, 근거에서 도출한 판단, 미확인 항목을 구분한다.
5. 결과에 조사 날짜, 질문, 핵심 결과, 관련 파일·출처 URL, 선택지의 차이, 남은 결정을 한국어로 적는다.

## 경계

조사는 문서만 변경한다. 소스·DB 구조·환경 설정을 바꾸거나 브랜치·커밋·배포를 만들지 않는다. 연결 문자열·키·개인 데이터는 문서에 넣지 않는다. 연결 도구가 없으면 조사하지 못한 범위를 표시하고 확보한 자료로 진행한다.

```text
$research context/research/데이터구조.md
/research 로컬 PostgreSQL과 Neon 연결 차이를 정리해줘
```
