# 기능명

## 식별자와 상태

- 스펙 ID: 파일명과 연결되는 고유 식별자
- 상태: 초안 / 확인 필요 / 대기 / 진행 중 / 검토 중 / 완료
- 문서 작성만으로 구현이나 검증을 완료 처리하지 않는다.

## 근거 자료

- 원본 문서: 자료 ID·위치, 기준 버전 또는 날짜, 관련 요구사항 번호·절/페이지
- 사용자 흐름·정책: 자료 ID, 관련 단계·분기·정책 조항. 미제공·미확인은 그대로 표시
- Figma: 있는 경우 자료 위치, 대상 화면·프레임, 기준 버전 또는 확인 날짜
- 자료 확인 상태: 직접 확인한 범위와 읽지 못한 부분
- 충돌·누락: 원본에 없는 내용과 결정이 필요한 사항

원본 요구사항, 합의된 변경, 구현을 위한 제안을 구분한다. Figma가 없으면 없다고 기록한다.

## 선행 작업

선행 스펙 ID·경로와 필요한 이유를 적는다. 없으면 `없음`으로 표시한다. 구현을 막는 미정 사항은 별도로 적는다.

## 사용자 흐름

시작 조건 → 사용자 행동 → 시스템 처리 → 보이는 결과를 작성한다. 빈 상태·로딩·실패·재시도도 포함한다.

## 수용 기준

- [ ] AC-1: 주어진 조건에서 사용자가 행동하면 관찰 가능한 결과가 나온다.
- [ ] AC-2: 잘못된 입력이나 권한 없는 요청에 대한 결과가 정의되어 있다.

## 데이터와 인터페이스

엔터티, 필드, 관계, 제약조건, 소유권, 마이그레이션, Server Action 또는 Route Handler 계약을 필요한 범위만 작성한다.

## 구현 계획

변경할 파일·모듈, 작업 순서, 기존 패턴을 적는다. 변경 이유가 없는 새 라이브러리는 추가하지 않는다.

## 검증 계획

각 수용 기준을 원본 요구사항·유저 플로우 단계/분기·정책과 연결하고 어떤 명령·테스트·브라우저 행동으로 확인할지 적는다. Figma가 있으면 관련 화면·상태와 비교할 화면 크기·방법을 함께 기록한다. DB 변경은 마이그레이션 검증과 운영 적용 순서를 포함한다.

## 미정 사항

결정해야 할 내용과 이미 합의된 내용을 구분한다.

## 결과

구현 후 수용 기준별 결과와 실제 검증 근거를 작성한다.
