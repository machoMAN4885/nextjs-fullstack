# 스펙 분석에 사용할 원본 자료

PRD, 유저 플로우, 업무 정책, 화면 정의, 데이터 정의, 회의 결정 등 이미 가진 자료를 이 폴더에 모을 수 있다. PRD가 필수인 것은 아니다. 실제 제품 자료는 아직 들어 있지 않으며, 이 README는 보관 방법 안내다.

필요한 폴더만 만들어 사용한다. 아래 파일과 하위 폴더는 배치 예시이며 제공된 자료가 아니다.

```text
context/inputs/
  prd/           제품 목적·범위·요구사항
  user-flows/    사용자 역할·흐름·분기·실패 동작
  policies/      권한·취소·보관 등 업무 규칙
  design/        화면 정의·Figma 링크·이미지
  data/          데이터 정의·용어
  decisions/     합의한 결정과 회의 기록
```

폴더 이름이나 파일 형식을 강제로 맞출 필요는 없다. 기존 폴더 구성을 유지해도 된다. 원본 버전과 확정된 자료가 무엇인지 표시하고 Figma 링크는 관련 사용자 흐름·화면 설명과 함께 문서에 적는다.

템플릿 루트에서 다음과 같이 요청한다.

```text
$prd-to-specs context/inputs/
하위 폴더의 자료를 함께 읽고 요구사항·유저 플로우·정책을 연결해줘.
문서 안에 Figma 링크가 있으면 MCP로 관련 화면도 분석해줘.
자료 목록과 미확인 범위, 충돌을 기록하고 여러 기능 스펙 초안을 작성해줘.
```

AI는 읽은 자료의 근거를 스펙에 연결하고, 읽지 못한 자료는 이유와 함께 남긴다. 문서 수나 폴더 수가 스펙 수를 결정하지 않는다. 자료가 변경되면 같은 입력으로 변경 사항 반영을 요청한다.

전체 흐름은 [사용 가이드](../../사용가이드.md)를 따른다.
